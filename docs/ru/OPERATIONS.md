# Обновление, данные и безопасность

## Обновление и откат
Сохраните резервную копию базы WordPress и каталога плагина штатным способом вашего сайта. Установите новый ZIP как обновление, без предварительного удаления плагина. Деактивация сохраняет настройки и кэш. Для отката деактивируйте плагин, замените его каталог предыдущей версией и активируйте снова. Для полного возврата состояния сайта восстановите базу из резервной копии. После обновления или отката проверьте настройки и формы.

Удаление через WordPress запускает uninstall и удаляет настройки и таблицу кэша адресов. Краткоживущий кэш баланса может оставаться до обычной очистки WordPress. Резервные копии сайта могут сохранять удалённые данные: управляйте ими согласно собственной политике хранения.

## Обработка данных
После сохранения ключа и принятия соглашения административный запрос баланса возможен при открытии настроек и по кнопке. Ручная проверка отправляет введённый адрес. Автоматические проверки требуют отдельного включения. Запрос содержит адрес и ключ авторизации, без остальных полей формы, паролей, платёжных данных и IP посетителя. Сервис также получает сетевой адрес сервера WordPress и обычные метаданные запроса.

Ключ хранится в настройках WordPress, проверенные адреса и результаты — в локальной базе сайта. Просроченные результаты не используются и очищаются при последующих записях; срок кэша не означает немедленное физическое удаление. Экспорт и удаление персональных данных WordPress включают локальный кэш, но не записи внешнего сервиса. Резервные копии сайта могут содержать настройки и кэш: ограничивайте доступ к ним.

Документы сервиса: https://zbounce.net/privacy.html, https://zbounce.net/terms.html и https://zbounce.net/license.html. Владелец сайта объясняет посетителям собственную обработку данных. Установка плагина сама по себе не подтверждает соблюдение законодательства.

## Безопасность и сообщения об уязвимостях
Административные API-действия требуют `manage_options` и корректного nonce. Публичные формы проверяются включёнными интеграциями; отдельный тестер доступен только администраторам. Ключ не передаётся в браузер. Ввод очищается, вывод экранируется, результаты браузера вставляются как текст. Плагин не записывает собственный диагностический журнал.

Используйте HTTPS, обновляйте WordPress и интеграции, ограничивайте административный доступ и защищайте резервные копии. Об уязвимостях сообщайте лично на support@zbounce.net с версиями и шагами воспроизведения, без ключей и персональных данных. Не устанавливайте тестовый MU-плагин с подменой API на рабочий сайт.
